# System V IPC로 구현한 멀티프로세스 격자 게임

10×10 보드에서 두 팀이 겨루는 Linux 시뮬레이션입니다. 플레이어 한 명은 독립된 C 프로세스 하나입니다. 각자 다른 주소 공간에서 움직이면서도 같은 칸을 동시에 차지하지 않아야 하고, 네 명이 모여야 게임을 시작하며 마지막 플레이어가 떠나면 커널 자원을 회수해야 합니다. 이를 위해 보드, 동기화, 팀 통신에 서로 다른 System V IPC 기능을 사용했습니다.

## 실행해 보기

Ubuntu 22.04 x86-64에서 GCC 11.4와 GNU Make로 빌드했습니다. 저장소 루트에서 실행합니다.

```sh
make
```

같은 Linux IPC 네임스페이스에서 터미널 다섯 개를 열고 아래 순서대로 실행합니다. 관전자 화면에서 `A`는 팀 0, `B`는 팀 1, `0`은 빈 칸입니다.

| 터미널 | 명령 |
|---|---|
| 1 · 관전자 | `./lemipc viewmode` |
| 2 · 팀 A 첫 번째 플레이어 | `./lemipc 0` |
| 3 · 팀 A 두 번째 플레이어 | `./lemipc 0` |
| 4 · 팀 B 첫 번째 플레이어 | `./lemipc 1` |
| 5 · 팀 B 두 번째 플레이어 | `./lemipc 1` |

네 번째 플레이어가 참가하면 게임이 시작됩니다. 양옆이나 위아래에서 같은 적 팀 두 명에게 둘러싸이면 해당 플레이어가 탈락합니다. 도중에 끝내려면 **플레이어 터미널 하나에서** `Ctrl+C`를 누릅니다. 다른 플레이어도 종료 상태를 읽고 퇴장하며, 관전자는 해당 게임의 공유 메모리가 사라지면 종료합니다.

## 게임이 진행되는 과정

| IPC 자원 | 보관하거나 조정하는 것 | 필요한 이유 |
|---|---|---|
| 공유 메모리 | 보드, 팀별 생존 인원, 게임 상태 | 모든 플레이어가 같은 보드를 읽고 이동 결과를 기록합니다. 관전자는 읽기 전용으로 연결합니다. |
| 세마포어 두 개 | 보드를 수정할 권한, 등록된 플레이어 프로세스 수 | 플레이어들이 참가·이동·탈락 처리를 차례로 수행하고, 마지막 퇴장자를 판별합니다. |
| 메시지 큐 한 개 | 초기 좌표, 시작 신호, 팀별 추적·사망 메시지 | 각 프로세스가 메시지 유형을 지정해 자신이 기다리는 사건을 꺼냅니다. |

1. **방을 만듭니다.** 첫 플레이어가 공유 메모리를 배타적으로 생성하고 세마포어와 메시지 큐를 준비합니다. 나중에 도착한 플레이어는 같은 자원에 연결합니다. 키는 `ftok("/tmp", 'A')`로 정해져 있어 기본 설정에서는 같은 IPC 네임스페이스에서 한 게임을 공유합니다. [자원 생성과 접속](src/system.c)
2. **참가를 확정합니다.** 보드를 잠근 채 팀 정원을 확인하고 초기 위치와 인원을 기록합니다. 두 팀에 두 명씩 모이면 마지막 참가자가 시작 메시지 네 개를 넣습니다. 각 플레이어가 하나씩 받은 뒤 이동 루프로 들어갑니다. [참가와 시작 처리](src/player.c)
3. **한 번씩 이동합니다.** 팀이 보낸 추적 좌표가 반경 3 이내이면 목표로 삼고, 목표가 없을 때는 주변 여덟 방향 중 하나를 시도합니다. 이동할 칸이 비어 있는지 확인하고 기존 칸과 새 칸을 같은 잠금 안에서 갱신합니다. 사망 알림은 추적 좌표를 덮어쓰지 않도록 메시지 종류를 구별합니다. [이동과 탈락 규칙](src/game_algorithm.c)

## 관전자가 남아도 게임을 끝내기

초기 구현에서는 공유 메모리에 연결된 수로 마지막 플레이어를 판단했습니다. 마지막 플레이어의 퇴장과 관전자의 읽기가 겹치면 관전자도 참가자로 계산되어, 더 이상 정리를 맡을 플레이어가 없는데 IPC 자원과 관전자가 남았습니다.

현재는 **등록된 플레이어 수를 별도 세마포어로 셉니다.** 관전자는 이 값을 바꾸지 않습니다. 마지막 플레이어가 퇴장하면 세마포어, 메시지 큐, 공유 메모리를 제거하고 관전자도 종료할 수 있습니다. 관전자의 읽기 전용 연결을 마지막 퇴장까지 유지한 테스트를 16회 반복해 이 경로를 확인했습니다. [수정 전 재현 기록 F01](portfolio_audit/failures.md) · [현재 회귀 테스트 B13](portfolio_audit/tests/run_baseline.py)

## 테스트와 확인 범위

```sh
make audit
```

Python 3과 util-linux의 `unshare`가 필요하며 사용자·IPC 네임스페이스 생성을 허용하는 Linux에서 실행해야 합니다. 테스트가 독립된 IPC 네임스페이스를 만들고, 종료할 때 출력 경로의 `test_results.json`에 사례별 판정을 남깁니다.

Ubuntu 22.04에서 23건 중 **20건이 통과**했습니다. 나머지 3건은 `SIGKILL`, `SIGTERM`, 강제 종료 뒤 재시작입니다. 세마포어의 `SEM_UNDO`는 종료된 프로세스의 연산을 되돌리지만, 그 플레이어가 공유 메모리에 써 둔 말과 인원까지 복구하지는 않습니다. 이 경로에서는 보드에 플레이어가 남거나 다음 실행이 이전 IPC 자원에 연결될 수 있어 부분 통과로 기록합니다.
